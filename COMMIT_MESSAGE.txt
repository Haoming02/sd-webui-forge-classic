Fix ControlNet batch processing with memory-optimized sub-batching

Resolves long-standing issues where ControlNet batch mode would only process
the first image or fail with memory errors on large batches.

## Issues Fixed

1. **Early Loop Termination (Issue #208, #287)**
   - Removed break statement that stopped processing after first image
   - Allows all batch images to be preprocessed regardless of output type

2. **Incorrect Image Alignment (Issue #260, #410)**
   - Fixed modulo-based cycling that repeated first image
   - Implemented proper 1:1 mapping between inputs and outputs

3. **Memory Optimization (Issue #55)**
   - Added sequential sub-batching to prevent OOM errors
   - Processes images in configurable chunks (default: 2 per iteration)
   - Memory freed between iterations for large batches

4. **Error Handling**
   - Added safety checks for missing cached parameters
   - Prevents KeyError crashes when model loading fails
